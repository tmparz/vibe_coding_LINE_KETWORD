# 講師與助教執行手冊

## 角色分工
講師阿茲：設計需求、講解「為什麼」、示範完整系統、帶 AI 除錯。助教：課前帳號檢查、投影、逐桌排障、記錄共通問題。學員：實際操作帳號、自己保管密鑰、逐步驗收、帶走自己的 Worker 作品。

## 兩日進度關卡（投影 QR / 群組連結可後補）
D1 關卡 A（1:30）：OA 可登入並知道 Messaging API 在何處啟用。
D1 關卡 B（3:20）：D1 中可看到 FAQ 五筆。
D1 關卡 C（5:15）：一個人在 LINE 傳問句得到 Gemini 依 FAQ 回覆。
D1 終點（6:00）：含超出範圍問題也可適當轉真人。
D2 關卡 A（1:50）：產品／課程資料在後台可編輯。
D2 關卡 B（3:05）：LINE 可收到清單、成功建立訂單。
D2 關卡 C（4:40）：Rich Menu 及管理員通知正常。
D2 終點（6:00）：展示、完成驗收並交出流程圖。

## 分流與防掉隊
- 紅燈：帳號／權限問題，交給助教處理；先讓學員操作講師 Demo，以免整班等待。
- 黃燈：AI 程式碼無法執行，回到 GitHub 基準模板並逐項比較，禁止一次讓 AI 重寫整個專案。
- 綠燈：已達門檻者，嘗試自定 FAQ、增加商品或調整選單，不插入新的核心依賴。
- 任何需要蒐集密鑰、登入正式商家帳號的排障，改由學員本人操作，講師只口頭引導。

## 常見錯誤診斷
- LINE 不回覆：先看 LINE webhook Verify → Worker logs → secret 名稱 → D1 是否有 FAQ → Gemini 是否有配額。
- 回覆兩次：關閉或調整 LINE OA 內建自動回覆，並確定 LINE 平台 webhook 沒重送。
- FAQ 幻覺：減少含糊資料，測試「資料不足」轉真人。
- 訂單超賣：確認 DB trigger 已建立，重複 webhook event 不得重複下單。
- Token 外洩：立即輪替，確認 repo/git history 等公開紀錄。

## 課後 30 天練習建議
第 1 週：新增 10 條 FAQ；第 2 週：改商品文案；第 3 週：加入人工轉接話術；第 4 週：完成展示與安全檢核。此為建議社群作業，不承諾就業／正式商用系統。
