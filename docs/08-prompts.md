# 課堂可直接複製的 AI 協作提示詞

以下提示詞**不填任何真實 Key 或 Token**，只給 AI 技術規格與驗收條件。

## 提示詞 1：第一天的 FAQ 功能
「你是 Cloudflare Worker 和 LINE Messaging API 程式協作教練。請先閱讀目前專案檔案，先解釋資料流及每個檔案責任，再提出最小變更計畫。我要做繁體中文 LINE FAQ：資料在 D1 的 FAQs；Worker 要使用原始 request body 驗證 LINE x-line-signature；AI 使用 GEMINI_API_KEY Worker secret；回答只用已啟用 FAQ，沒有資料就轉真人。不要使用外部公開金鑰，不要創造不存在的營業規則。請先提供測試清單，經我同意再修改程式。」

## 提示詞 2：改寫自己的 FAQ 規格
「我的服務是【類型】，常見問題是【五個不含個資的問題與確定答案】。請協助把資料整理為可寫入 D1 的 FAQ，每筆包含 question、answer、tag、active，內容保持繁體中文，不能承諾未提供的條件。先提出資料表與 SQL，再列出五種反例測試。」

## 提示詞 3：第二天的接單 MVP
「請以現有的 LINE FAQ Worker 為起點新增商品展示與文字接單。場景是【實體商品／課程名額】，商品欄位 sku、title、description、price、stock、active。顧客在 LINE 傳『商品』時顯示清單，傳『訂購 P001』才可以建立訂單。不接受由 Gemini 自動呼叫下單。請規劃資料表、名額檢查與防重複 webhook，後台可新增修改商品與查看訂單。先給一頁功能規格、你準備改的檔名、三個測試案例，不要一次大改。」

## 提示詞 4：AI 排錯（最常用）
「以下是我執行的步驟：【步驟】；預期：【結果】；實際：【結果】；錯誤訊息（已遮蔽金鑰及個資）：【貼上錯誤】。請只提出最可能的三個原因及驗證方法。優先不修改程式；若確實需要修改，先列出差異與回滾方式。」

## 提示詞 5：功能驗收
「請審查這份 Worker 程式是否滿足：(1) 簽章驗證、(2) Secret 不會暴露、(3) FAQ 超出範圍不亂答、(4) 下單不超賣、(5) 重送事件不重複扣庫存、(6) 錯誤能追查。請用『通過／需驗證／不通過』表格評分，不要在沒有測試證據時宣稱完成。」

## 提醒
提示詞能引導 AI 協作，並不取代實際程式測試。秘密只能由本人輸入 Cloudflare 的 secrets 設定。
