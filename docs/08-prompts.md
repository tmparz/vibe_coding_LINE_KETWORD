# 學員可直接複製的 Vibe Coding 提示詞

## Day 1：整理靜態 FAQ
「我要做 LINE 官方帳號自然語言 FAQ。請幫我把以下已確認的問答整理成可貼入 src/faq-data.js 的 JavaScript 陣列，包含 question 與 answer：〔貼上五到十題不含個資的 FAQ〕。顧客用口語或換句話問時，要把所有 FAQ 和顧客問題一起送給 Gemini，僅依 FAQ 回答，沒有答案引導真人客服。**不要建立 D1、R2、向量搜尋或資料表**。先檢查我提供的資訊是否有矛盾。」

## Day 1：串接 LINE 與 Gemini
「請閱讀現有 src/faq.js、src/index.js、src/line.js。協助我理解 LINE 訊息如何經 Worker 驗證簽章，再將顧客提問和完整 FAQ 傳給 Gemini，最後回覆 LINE。金鑰只能用 Worker secrets。先列出部署和測試步驟，絕對不要要求我把 Key 貼給 AI。」

## Day 2：D1 預約系統
「沿用第一天已完成的 LINE Worker，新增**獨立**的預約功能。請使用 D1 只存 slots（時段/容量）與 bookings（待確認預約/事件識別），不要搬移 FAQ 到 D1。顧客傳『時段』可查可預約時段，傳『預約 S001』才建立預約。請加入滿額保護、同事件重送不重複占名額、同一使用者同時段不可重複預約、管理員查看紀錄。先交付一頁規格與三個反例測試，再逐段實作。」

## Debug 提示詞
「我做了〔操作步驟〕，預期〔結果〕，實際〔結果〕；錯誤訊息已遮蔽金鑰〔貼上〕。請先判斷這是第一天的 FAQ 路徑，還是第二天的 D1 預約路徑，只提出三個最可能原因及驗證順序，不要大幅重寫程式。」

所有 Prompt 都不得包含真實密鑰、顧客個資或正式帳號機密。
