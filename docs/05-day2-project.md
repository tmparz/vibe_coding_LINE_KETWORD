# 第二天專題：LINE 預約系統

第二天以 [vibe-coding-course-guide](https://github.com/tmparz/vibe-coding-course-guide)（`two-day-v2` 分支）根目錄的 Step 1–10 為準。學員在網頁填好欄位，頁面會組出一段整合提示詞，交給 Codex 建立整套系統。

> 本 repo 的 `wrangler.day2.jsonc`、`src/bookings.js`、`migrations/` 是早期「時段＋預約 S001」版本，**課程不再使用**，保留作為老師參考。

## 和第一天的關係

- 同一個 LINE 官方帳號、同一把 Gemini 鑰匙，第二天頁面會自動帶入第一天填的資料。
- 第一天的 FAQ 保留：客人一般的問題，照樣由 Gemini 依 FAQ 回答。
- 第一天老師示範的「真人和機器人同時回覆」，第二天用後台解決。

## 功能範圍

| 功能 | 說明 |
|---|---|
| 商品 | 名稱、價格、庫存、上架狀態、有效期間；後台可新增修改 |
| 圖文選單 | 左「瀏覽商品」、右「聯絡客服」，兩個按鈕都送出真正的文字 |
| 預約 | 商品輪播的「立即預約」送出「👉 我要預約【商品名稱】」→ 建立訂單、扣庫存 |
| 通知 | 客人收到確認，管理員收到推播 |
| 後台：訂單 | 列出訂單；刪除訂單時把庫存加回去 |
| 後台：客人狀態 | 真人接手中的客人、手動結束真人接手、設定某位客人不用 AI |
| 後台：問題紀錄 | AI 答不出來的問題與時間 |

訊息分流規則見 [03-line-setup.md](03-line-setup.md#day-2訊息分流)。

## 一定要能證明

- 客人自己打「我要預約」：AI 引導點選單，**沒有**建立訂單。
- 按「聯絡客服」後再傳訊息：機器人不回應，管理員收到通知。
- 真人接手中按預約按鈕：照樣建立訂單。
- 問一題 FAQ：AI 依第一天的 FAQ 回答。
- 後台看得到 AI 答不出來的問題。

## 不包含

金流、取消改期流程、會員、多角色權限、正式的個資與安全審查。
